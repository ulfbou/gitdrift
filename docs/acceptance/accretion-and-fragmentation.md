# Accretion and fragmentation acceptance

## Purpose

This document defines reproducible acceptance scenarios for cumulative and dispersed semantic evolution.

## Fixture contract

Each scenario declares immutable history, transitions, snapshots, fragment and concept identities, extractors, obligations, comparison windows, mechanical policy, expected accounting, completeness, and a mutation sentinel.

## Scenarios

### Many small changes producing contradictory authority

No single large change exists, but successive transitions create active contradictory authority. Gitdrift preserves the chain and builds a cumulative case referencing the affected obligations.

### Healthy decomposition

One artifact is split across focused descendants while required facts, authority, navigation, and enforcement remain accounted for. The result records decomposition without semantic-loss judgment.

### Split with lost requirement

A required source fact has no supported descendant in otherwise complete scope. The case records source evidence, accounting, counterevidence search, and the affected obligation.

### Split with duplicated and divergent fragments

A source representation is duplicated and descendants later conflict. Gitdrift records duplication, divergence, roles, authority, and distinct provenance.

### Generated-format churn

Broad generated or formatting changes are retained in raw history and reversibly suppressed from a configured semantic projection without strengthening completeness.

### High-frequency file with no regression

An artifact changes frequently while evaluated obligations remain satisfied or strengthened. Frequency selects deeper analysis but produces no regression verdict.

## Acceptance rule

A scenario passes only when raw transitions remain available, windows and policies are reproducible, fragmentation accounting is explicit, authority roles remain distinct, omitted evidence is inventoried, native output validates, completeness is accurate, and the mutation sentinel passes.
