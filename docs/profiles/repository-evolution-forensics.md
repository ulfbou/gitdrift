# Repository-evolution forensics profile

## Purpose

This profile performs deeper longitudinal analysis of how repository artifacts, fragments, concepts, facts, and obligations accumulate, disperse, duplicate, diverge, disappear, and reappear.

It remains inside Gitdrift because these histories are needed to explain regression and divergence. It does not expand into developer-performance, organizational, host, disk, or memory forensics.

## Inputs

A request declares selected subjects, immutable states and refs, traversal policy, comparison windows, mechanical-change policy, extractors, obligations, case-selection rules, and evidence limits.

## Analytical depth

The profile composes repository evidence, artifact and fragment lineage, semantic facts, obligations, and cases. It may evaluate adjacent, rolling, epoch, obligation-relative, and user-selected windows.

It supports evidence-backed candidates for:

- cumulative semantic accretion;
- one-to-many and many-to-one lineage;
- semantic fragmentation;
- duplicated representations that later diverge;
- residual or unaccounted content;
- authority dispersed across artifacts; and
- long-lived contradictions.

## Selection signals

Change frequency, churn, file size, branch count, fragment count, and transition count may select subjects or windows for deeper analysis. They are descriptive signals, not findings or judgments.

## Accretion analysis

Accretion analysis evaluates cumulative semantic change across explicit windows. It records concepts, roles, facts, obligations, contradictions, and unresolved residue without assuming that growth or frequent modification is harmful.

## Fragmentation analysis

Fragmentation analysis accounts for transferred, transformed, duplicated, residual, divergent, unaccounted, authoritative, and non-authoritative representations. Healthy decomposition remains distinguishable from semantic loss.

## Mechanical change

Raw evidence is always retained. Declared formatting or generated changes may be reversibly excluded from a semantic projection under the mechanical-change policy.

## Cases and output

The profile may produce cumulative-accretion, semantic-fragmentation, contradiction, possible-loss, and insufficient-evidence cases. Every case identifies its window, selected evidence, omitted evidence, completeness, and reproduction boundary.

Native JSON remains authoritative. The profile performs no repository mutation and does not infer intent or authority from activity metrics.
